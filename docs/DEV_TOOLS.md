# 개발자 도구 설계

**상태: 승인(2026-11-25), 구현·검증 완료.** 결과와 설계에서 달라진 점은 7절.

## 1. 왜 필요한가

- **확인할 상황을 만들 수 없다.** 3단계 검증에서 BossUndead(스테이지 1 보스)가 서는 위치(D9)를 S24에서 보지 못했다. 기기 세이브가 스테이지 3인데, 스테이지를 옮기거나 새로 시작할 방법이 에디터 메뉴(`IdleGame/Reset Save Data`)뿐이다.
- **4단계(흐름)를 검증하려면** 스테이지 이동, 보스 바로 도전, 배속이 반복해서 필요하다.
- UI_DESIGN 9장 2차에 "디버그 도구(치트 메뉴: 골드/레벨 설정, 창 스택·입력 차단 이유 오버레이)"로 잡혀 있던 것 중 **치트 메뉴를 앞당긴다.** 오버레이는 2차에 그대로 둔다.

## 2. 원칙

1. **릴리스 빌드에는 코드가 없다.** 진행도는 클라이언트 소유이고 서버는 이상치만 검사한다([SERVER_DESIGN.md](SERVER_DESIGN.md) 2장). 그래서 숨겨 둔 치트 메뉴는 그대로 악용 경로가 된다.
2. **개발 도구 전용 게임 API를 만들지 않는다.** 도구는 게임이 원래 쓰는 길을 부른다. 도구 때문에 게임 쪽에 입구를 새로 만든다면 그 입구는 정식 기능이어야 한다. 이번에는 흐름 재시작(T4)과 진행도 교체(T5, 서버 롤백 경로)가 그렇다.
3. **세이브 원칙은 개발 도구에도 적용된다.** 덮어쓰기 전에 자동으로 백업하고, 복원은 검사를 통과한 것만 받는다.
4. **명령과 화면을 나눈다.** 명령은 순수 C#(`DevCommands`)이고, 패널은 그 명령을 부르기만 한다. 그래서 Claude는 에디터에서 Pipeline `script eval`로, 테스트는 코드로 같은 명령을 쓴다.

## 3. 결정

### T1. 포함 범위: 에디터와 개발 빌드, 별도 어셈블리

- `Assets/Scripts/DevTools/`에 어셈블리 `IdleGameProtoType.DevTools`를 둔다. define constraint는 `UNITY_EDITOR || DEVELOPMENT_BUILD`다.
  - 릴리스 빌드에서는 어셈블리가 통째로 컴파일되지 않는다. 파일마다 `#if`를 거는 방식은 하나를 빠뜨리면 새는데, 이 방식은 그럴 수가 없다.
- 의존 방향은 DevTools → Runtime 한쪽이다. 게임 코드는 도구를 모른다.
- 기기에서 확인하는 빌드는 개발 빌드로 만든다. 성능 측정은 릴리스 빌드로 한다.
- 대안은 자체 define(`IDLE_DEV_TOOLS`)으로 릴리스 설정 빌드에도 넣는 것이다. QA 빌드가 필요해지면 그때 더한다.

### T2. 연결: 조립 지점의 "조립 끝" 신호 하나

- `GameInitializer`가 조립을 끝낸 뒤 신호(`Initialized`)를 한 번 내고, 세션과 GameManager 등 조립한 객체를 넘긴다.
- DevTools는 `RuntimeInitializeOnLoadMethod(AfterSceneLoad)`로 자기 오브젝트를 만들고 그 신호를 구독한다.
- 이렇게 하면 조립 지점은 도구를 모르고, 도구는 조립 순서 밖에서 싱글턴을 뒤지지 않는다.
- `UIRoot`는 `InputBlocker`를 읽기 전용으로 내보낸다(T3에 필요).

### T3. 화면: IMGUI 패널

- 릴리스에서 빠져야 하므로 도구는 에셋을 가질 수 없다. 창 프리팹을 `WindowRegistry`에 등록하면 릴리스 빌드에 스크립트가 빠진 프리팹이 들어간다.
- IMGUI(`OnGUI`)는 코드만으로 그려져서 개발 도구에서 흔히 쓴다.
- 이것은 CLAUDE.md "새 팝업은 `UIWindow`" 규칙의 예외다(게임 UI가 아니다). 승인되면 UI_DESIGN 11장에 기록한다.
- **열기:** 화면 구석의 작은 `DEV` 버튼으로 연다. 자리는 게임 UI와 겹치지 않는 곳을 기기에서 확인해 정한다. 에디터에서는 `` ` `` 키로도 연다.
- **입력 차단:** IMGUI와 uGUI는 같은 터치를 둘 다 받는다. 막지 않으면 패널 버튼 밑의 게임 버튼도 눌린다. 그래서 패널이 열려 있는 동안 `InputBlocker`로 게임 UI를 막는다. 이 규칙은 기존 입력 차단 시스템을 그대로 쓴다.
- **버튼 크기:** 화면 DPI 기준으로 정한다(손가락 크기, 약 9mm).
- 대안은 코드로 만든 uGUI다. 터치 스크롤과 모양은 낫지만 코드가 몇 배다. 항목이 늘어 스크롤이 필요해지면 그때 바꾼다.

### T4. 흐름 입구 하나: `GameManager.RestartAt(int stageNumber)`

- 순서: 페이드 → 인카운터 정리(스테이지가 바뀌면 이전 스테이지 몬스터 풀 정리) → 스테이지 초기화 → 플레이어 부활 → 저장 → 스폰 루프.
- **지금의 두 갈래를 이 하나로 합친다.** 사망은 `RestartAt(지금 스테이지)`, 클리어는 `RestartAt(다음 스테이지, 마지막이면 그 스테이지)`가 된다(마지막 스테이지를 다시 하는 지금 동작을 유지). 지금 `TransitionToStageInternal(canNext)`에 있는 분기(인자 없는 `stageManager.Initialize()`로 다시 초기화하는 갈래 포함)가 사라진다. 도구의 스테이지 이동도 같은 길을 쓴다.
- 전환 중(페이드 중)에 다시 부르면 무시하고 경고한다.
- 4단계에서 EncounterDirector로 옮길 때 이 입구 하나만 옮기면 된다.
- **옮김(2026-11-25, 전투 4-A):** 입구는 `EncounterDirector.RestartAt(스테이지)`가 됐다. 결과(`Accepted`/`Busy`/`NoSuchStage`)를 바로 돌려주고 실행은 다음 고정 단계에서 한다. 전환은 시뮬레이션 시간이고, 사망·클리어도 디렉터 안에서 같은 전환을 쓴다([COMBAT_ARCHITECTURE.md](COMBAT_ARCHITECTURE.md) 10절). `GameManager.RestartAt`과 `IsTransitioning`은 없어졌다. `LoadSnapshot`(T5)은 재시작을 먼저 받아 둔 뒤 `Apply`한다(받지 못하면 진행도를 바꾸지 않는다).

### T5. 진행도 교체: `GameManager.LoadSnapshot(PlayerSaveData)`

- 순서: 검사(`SaveDataValidator`, 저장할 때와 같은 검사) → `session.Apply` → `RestartAt(세션의 스테이지)`(저장 포함).
- 새로 시작, 백업 복원, 레벨 지정이 모두 이 하나를 쓴다.
- SERVER_DESIGN 2장의 "서버가 거절하면 마지막 승인 스냅샷으로 되돌린다"가 쓸 경로를 먼저 만드는 셈이다. 도구가 그 첫 사용자다.

### T6. `Apply`가 실행 중에도 완전하게 (발견한 빈틈)

- **빈틈:** 지금 `PlayerStats.LoadSave`는 레벨, 경험치, 업그레이드, 장착 슬롯이 바뀌었다는 알림을 내지 않는다. 저장 사건을 피하려고 일부러 그렇게 했다.
  - 시작할 때 한 번만 부를 때는 문제가 없다.
  - 실행 중에 부르면 HUD(레벨, 경험치, HP 바), 캐릭터 탭, 스킬 슬롯 바, 캐릭터 능력치(최대 HP, 공격력), 장착 스킬이 옛 값으로 남는다. 골드만 갱신된다. 코드에서 구독자를 확인했다.
  - 서버 롤백도 같은 문제를 겪는다. UI_DESIGN 10-2는 "값만 덮어쓰면 화면이 따라온다"고 적었지만, 레벨과 경험치가 아직 반응형이 아니라서 성립하지 않는다.
- **해결:**
  - `LoadSave` 끝에서 저장을 일으키지 않는 사건 `PlayerStats.OnReloaded`를 하나 낸다.
  - 구독자(캐릭터, HUD, 캐릭터 탭, 스킬 슬롯 바)는 이 사건을 받으면 전부 다시 읽는다.
  - 4단계에서 레벨, 경험치, 골드가 반응형 상태가 되면 이 구독은 반응형 구독으로 대체되어 지워진다. 과도기 장치임을 코드 주석에 적는다.
- **불변식(테스트):** 실행 중에 진행도 A에서 B로 교체한 뒤의 상태는 B로 새로 시작한 상태와 같다. 확인할 값은 캐릭터 능력치, 장착 스킬, HUD가 읽는 값이다.

### T7. 명령 목록 (첫 판)

| 묶음 | 명령 | 지나는 길 |
|---|---|---|
| 스테이지 | 번호로 이동, 이전/다음, 지금 스테이지 처음부터 | `RestartAt`(4-A부터 `EncounterDirector.RestartAt`) |
| | 보스전 바로 시작 → **4-A부터 "보스 도전"**(도전 가능할 때만) | 처음에는 `GameManager.EnterBossBattle`(가능 여부를 건너뜀). 4-A에서 보스 도전 버튼과 같은 명령 `EncounterDirector.RequestBossChallenge`로 바꿨다(D27: 건너뛰려면 개발 도구 전용 입구가 필요해 2장 원칙 2에 걸린다). 빨리 보려면 배속을 올린다 |
| 진행도 | 골드 더하기 | `Wallet.AddGold`(처치 보상과 같은 길) |
| | 경험치 더하기(다음 레벨 필요량만큼). 레벨업은 기존 LEVEL UP 버튼으로 | `PlayerStats.AddExp` |
| | 레벨 지정 | 스냅샷의 레벨을 고쳐 `LoadSnapshot` |
| 세이브 | 백업 만들기, 백업 목록에서 복원, 새로 시작(먼저 자동 백업) | 백업 파일 + `LoadSnapshot` |
| 시간 | 배속 ×1 / ×2 / ×5 / ×10 | `Time.timeScale` |
| 보기 | 판정 몸 표시(몸 중심 ± 반너비, 사거리) | `CombatWorld`를 읽기만 |

- **더하기와 바꾸기를 구분한다.** 더하는 명령은 게임의 보상 경로를 그대로 쓴다. 값을 통째로 바꾸는 명령은 모두 `LoadSnapshot`을 지난다. 그래서 모델에 치트용 setter가 생기지 않는다.
- **백업:** `<세이브 폴더>/dev_backups/<시각>.json`에 둔다.
  - 세이브 폴더는 `SaveProfile.SaveDirectory`를 따른다. 에디터의 프로필별 분리가 그대로 유지된다.
  - 개수 제한은 두지 않는다. 지우는 것도 데이터 삭제이기 때문이다.
  - 복원할 때는 `SaveDataValidator`를 통과한 백업만 받는다. 실패하면 세이브를 건드리지 않는다.
- **덮어쓰는 명령은 두 번 눌러야 실행된다.** 새로 시작, 복원, 레벨 지정이 해당한다. 첫 번째로 누르면 "한 번 더 누르면 실행"이 뜨고, 3초가 지나면 취소된다.
- **배속:** 고정 단계라 결과는 ×1과 같고, 화면 프레임당 단계 수만 늘어난다. 상한은 `Maximum Allowed Timestep`(1/3초)이다. 30fps 기기에서 ×10이면 프레임당 0.33초로 상한에 닿는다. 그때는 요청보다 느리게 돌 뿐 결과는 같다.
- **판정 몸 표시:** D9 확인(BossUndead가 서는 위치)에 바로 쓴다.

## 4. 범위 밖 (나중)

- **창 스택·입력 차단 이유 오버레이:** UI 2차에 그대로 둔다.
- **기기용 검증 세이브 프로필:** 실행 인자(`adb shell am start ... -e unity "-saveProfile claude"`)로 켠다. Claude가 기기에서 검증할 때 사용자 세이브를 건드리지 않게 하려는 것이다. 지금 `SaveProfile`은 에디터 전용이다. 이번에는 백업으로 대신하고, 필요해지면 더한다.
- **세이브 로드에 실패한 상태에서 복구:** 게임 기능으로 따로 한다(TODO "손상된 세이브의 복구 수단"). 조립이 중단되면 `LoadSnapshot`을 부를 GameManager가 준비되지 않은 상태다.

## 5. 검증 계획

- **EditMode 테스트:**
  - T6 불변식: 교체 뒤의 상태가 새로 시작한 상태와 같다.
  - 백업 복원이 손상 파일을 거부하고, 그때 세이브가 바뀌지 않는다.
  - 배속에서 처치 시각이 같다(가능하면).
- **배치 모드 플레이(`claude` 프로필):**
  - 스테이지 3 세이브에서 스테이지 1로 이동한 뒤 BossUndead 보스전을 보고, 판정 몸을 표시해 본다.
  - 새로 시작: 백업이 생기는지, 레벨 1·스테이지 1인지, HUD와 캐릭터 능력치가 새 값인지 확인한다.
  - 복원: 원래 값으로 돌아오는지 확인한다.
  - 사망과 클리어 흐름이 `RestartAt`으로 합친 뒤에도 같은지 확인한다(처치 시각 비교).
- **빌드:**
  - 릴리스 빌드에 DevTools 어셈블리가 없는지 확인한다.
  - 개발 빌드를 S24에서 확인한다: 패널, 터치, 게임 UI 차단, Android 뒤로가기.
- **기존 테스트 전부.**

## 6. 순서

전투 4단계(흐름) 앞에 둔다. 4단계 검증(스테이지 전환, 보스, 사망)에 바로 쓸 수 있고, 4단계는 `RestartAt` 입구 하나만 EncounterDirector로 옮기면 된다.

다른 순서도 있다. 4단계를 먼저 하면 레벨과 경험치가 반응형이 되어 T6의 과도기 사건이 필요 없다. 대신 4단계를 도구 없이 검증해야 하고, D9 확인도 그만큼 늦어진다.

## 7. 결과 (2026-11-25)

**구현:**

| 곳 | 내용 |
|---|---|
| `Assets/Scripts/DevTools/` (새 어셈블리) | `DevTools`(진입점, 열기·닫기, 입력 차단), `DevCommands`(명령), `DevBackupStore`(백업), `DevPanel`(IMGUI 패널), `HitboxOverlay`(판정 몸 표시) |
| `GameManager` | `RestartAt`(흐름 입구 하나), `LoadSnapshot`(진행도 교체), `IsTransitioning`. 사망·클리어가 `RestartAt`을 쓴다. 옛 `TransitionToStage(canNext)` 삭제 |
| `StageManager` | 쓰이지 않게 된 `TryAdvanceStage`/`IsCompleted` 삭제 |
| `PlayerStats` | `OnReloaded`(저장을 일으키지 않는 "다시 읽어라"), `MaxLevel` |
| 구독자 | `PlayerController`(능력치, 장착 스킬), `PlayerHud`, `StatUpgradePanel`, `SkillSlotBar`가 `OnReloaded`에서 다시 읽는다 |
| `GameInitializer` | `Initialized` 신호, `IsInitialized`, 조립한 객체 읽기 |
| `UIRoot` / `InputBlocker` | `InputBlocker`를 읽기 전용으로 내보냄. `Acquire(..., warnIfLong)` |

**설계와 달라진 점**
- **`InputBlocker.Acquire`에 `warnIfLong`을 더했다.** 10초 넘게 풀리지 않은 차단을 경고하는 기능(영구 잠금 디버깅용)이 있어서, 사용자가 닫을 때까지 쥐는 패널이 열 때마다 경고를 냈다. 이후 튜토리얼처럼 오래 쥐는 차단도 같은 옵션을 쓴다.
- **클리어 흐름:** 설계 초안은 "마지막 스테이지면 1로"라고 적었는데, 지금 동작은 마지막 스테이지를 다시 하는 것이었다. 동작을 바꾸지 않았다(T4 고침).
- **같은 스테이지를 다시 할 때는 스테이지 변경을 알리지 않는다.** 예전에도 사망 때는 알리지 않았다. 알리면 사망할 때마다 스테이지 안내가 뜬다.
- 패널 글자는 한국어다. IMGUI 기본 글꼴은 한글이 없지만 기기에서 운영체제 글꼴로 대체돼 보인다(아래 표).
- **기기에서 고친 것:** 백업을 하나 만들자 백업 목록 줄이 늘어 그 아래 버튼이 내려갔고, 바로 이어 누른 손가락이 다른 버튼(배속)을 눌렀다. 길이가 바뀌는 백업 목록을 패널 맨 아래로 옮기고, 상태·결과 줄을 한 줄 고정 높이로 했다. 판정 몸 상자의 아래 변을 피벗이 아니라 바닥선(`PlayAreaBounds.GroundY`)에 맞췄다(피벗이 발보다 위라 상자가 떠 보였다).
